# 音声処理・保存方式・手動テスト

[READMEへ戻る](../README.md)

この文書は，音声処理の方式と実機確認の手順をまとめたものです．実施済みの確認と未検証項目は[検証記録](../Tests/VALIDATION.md)を参照してください．

## 音声の取得と同期

- 相手側は非ミュートのprivate Process Tapと専用private Aggregate Deviceから取得します．通常のシステム出力を設定し直す処理はありません．AirPodsへの通常の再生を継続できる設計です．マイク音声を出力へ返すモニタリングは行いません．
- 特定アプリではCore Audioのプロセス一覧から，bundle IDの一致・子ID，またはアプリバンドル内の補助プロセスをまとめて選びます．録音中も約1秒ごとに更新します．関連を識別できない独立プロセスは含まれない可能性があります．その場合はMac全体を選んでください．新しい補助プロセスが音を出してから一覧更新までの音声は取り逃す場合があります．
- ブラウザーのアプリ単位取得には他タブの音声が含まれる場合があります．タブ単位の取得には対応していません．Mac全体では通知音なども含みます．
- マイクは`AVCaptureSession`と`AVCaptureAudioDataOutput`で選択デバイスを取得します．無断の代替マイクへの切り替えは行いません．切断・再接続を表示し，切断や実行エラーでは録音を停止して保存を試みます．自動再開は行いません．
- Zoomなどのミュート操作とは独立したマイク録音スイッチです．オフにするとマイクのCapture Sessionを停止します．録音中にオンへ変更する場合も，そのマイクの許可が必要です．切り替えでBluetoothのモードやTap形式が変わった場合は，明示的にエラー停止することがあります．
- Tapの`AudioTimeStamp.mHostTime`と，Capture Sessionの`synchronizationClock`からホスト時計へ変換したマイクPTSを共通の時間軸にします．到着順を使ってトラックを連結しません．開始差と欠落区間は無音として扱います．
- 実際の入力形式を読み取り，`AVAudioConverter`で48 kHzのfloat PCMへ正規化します．各入力の隣接PTS間隔で小さな時計ずれを補正し，大きな間隔は欠落として保持します．形式が変わったマイクはConverterを更新します．Tap形式変更，逆行時刻，600 msの待ち時間を超える入力遅延などで同期できなくなった場合は停止し，理由を表示します．無制限に遅延を蓄積しません．
- モノラルマイクは左右へ同じ信号を配置します．会議モードでは各音源を0.5倍（約−6 dB）で混合し，マイクのみモードではマイクを等倍で配置し，最終値を有限の±1に制限します．通常の2音源の単純加算によるクリップを防ぎます．入力段階ですでに歪んだ音は回復しません．
- コールバックでは入力コピーと上限付きキューへの引き渡しのみ行い，形式変換，混合，ファイル書き込み，メーター計算は専用ワーカーで行います．待機は最大48パケット，1パケット最大16384フレーム・8チャンネルです．リングは4秒固定です．全会議分のメモリーは保持しません．コールバックの短いバッファー割り当ては残っており，厳密なハードリアルタイム保証はありません．メーター／UI更新は最大10 Hzです．
- 待機中はTap・Aggregate Device・マイクを取得しません．会議候補の検知がオンの場合は，プロセスの入力利用メタデータの照会のみ継続します．停止・エラー時はIOProcを停止・破棄し，Aggregate DeviceとTapを破棄します．

## 保存と回復

完成ファイルは**M4A／AAC，48 kHz，ステレオ，目標192 kbps（CBR指定）**です．低サンプルレートの入力を48 kHzへ変換しても，失われた帯域や音質は改善しません．

録音中は完成ファイルと同じ保存先に，日時とランダムIDを付けた`.recording`フォルダーを作り，**30秒ごとの24-bit Apple Lossless／CAF**として混合音声を保存します．停止時に分割順に8192フレームずつ読み出し，AACへ一度だけ変換します．左右や音源ごとの巨大な別トラックは保持しません．完成ファイルは上記の会議名またはJST日時名になり，既存ファイルを上書きしません．

AACファイルはヘッダーだけでなく全体を再読み込みし，48 kHz・2 ch・AACと元の総フレーム数が一致することを確認してから回復フォルダーを削除します．失敗した場合は回復用データを保持します．書き込み中の異常終了では，未確定の最大約30秒と未書き込みバッファーが失われる可能性がありますが，閉じたCAFセグメントは独立して回復できます．電源断や物理ディスク障害まで保証するものではありません．

アプリ起動時，保存先に未完了フォルダーがあればメニューバーパネル右上の「…」→「未完了の録音を回復」から保存を再試行できます．読み取れないセグメントを飛ばして回復した場合は，**一部回復であることを表示し，元フォルダーを削除しません**．詳細はフォルダーの`Recovery-warning.txt`です．容量不足の場合は空きを確保するか，`.recording`フォルダー全体を別ディスクへ移して，アプリの保存先をその親フォルダーに変更して回復してください．デバイス切断時も保存を試み，保存できなければ同じ回復方法を使えます．

容量は内容で変わります．24-bitステレオ48 kHzの非圧縮相当は約**1.04 GB／時**で，ALACは通常これより小さくなります．完成AACは約**86 MB／時**です．録音と停止時の共存分を考え，目安として**1時間あたり1.5 GB以上**の空きを用意してください．空きが100 MB未満になると録音を停止します．最終変換用の空きが不足すれば回復データを残します．停止時の変換と再読み込みは録音時間に比例した処理ですが，メモリー使用量は一定です．

当初の分割AACパススルー案は，このSDKでM4A直接出力が拒否され，MPEG-4出力では31秒の音声が31.06秒として再読み込みされる挙動を検出したため採用していません．ALAC分割方式は容量と停止時CPUを使いますが，録音中の全データの保護と一度だけのAAC圧縮，正確な総フレーム数を優先した変更です．

## AirPodsと既知の制約

- 出力デバイスはmacOS側でAirPodsを選択してください．アプリ内ではAirPodsマイク，Mac内蔵マイク，USBマイクなどを独立して選べます．
- AirPodsを入力と出力に同時使用すると，Bluetoothの通話モードや機種・OSにより帯域と音質が制限される場合があります．48 kHz／192 kbpsで保存してもこの制約は解消しません．音質を優先する場合はAirPods出力＋Mac内蔵／USBマイク入力を比較してください．
- Appleの`configuresApplicationAudioSessionForBluetoothHighQualityRecording`は，インストール済みmacOS 27 SDKの`AVCaptureSession.h`で`API_UNAVAILABLE(macos, ...)`です．iOS向けの設定をmacOS対応と解釈していません．macOS 26以降のAirPods高音質機能を本アプリで明示的に有効化したり，Zoomと同時に利用できることは未確認です．
- AirPodsなどの出力形式が録音中に変わると，安全に停止する場合があります．再接続後に入力と出力を確認し，新しい録音を開始してください．
- 取得済み入力に対するノイズ除去，音声強調，エコーキャンセル，文字起こしは行いません．スピーカーとマイクの組み合わせでは相手の声がマイクにも入るため，イヤホン利用を想定しています．
- macOS 15以降をビルド対象にしていますが，実行確認環境はmacOS 27.0.1です．macOS 15・26での実機動作，Zoom／Teams／Google Meetでの完全なプロセス網羅，AirPodsの実録音，1時間の実デバイス音ずれ・メモリーは別途確認が必要です．

## 自動検証

```sh
./Scripts/test.sh
```

実アプリの`--self-test`実行経路を使い，録音許可や接続機器に依存せず以下を検証します．

- 開始オフセット，無音ギャップ，遅着エラー，コールバック到着順の違い，再生停止・再開時の保留パケット処理．
- 再生前に開始を待たないAggregate構成と，未受信／受信／再生休止の状態判定．
- モノラルの中央配置，2音源の混合レベルとクリップ回避，マイクオフ時のバッファー除去．
- 1時間相当，+100 ppmの合成時計ずれと固定長リング．実時間1時間の機器試験ではありません．
- キュー上限の超過通知．
- 実際の`AVAudioConverter`による24 kHzモノラルと44.1 kHzステレオの変換・混合．
- 31秒の分割CAF保存とAAC作成，全フレーム数の再読み込み一致，分割境界の音量維持．
- マイクのみの設定で再生音声が無効になることと，単独マイクの音量・中央配置．
- Zoom／Teams／Meetの候補判定，短い入力利用の除外，重複通知と録音中通知の抑止．
- Zoom／Teams／Meetのタイトルから議題を抽出し，一般的なアプリ名を除外，会議名付き回復データから完成ファイル名を生成．
- JSTの日時変換，回復用開始日時の保持，同名日時への連番，名前変更時の上書き拒否と変更後の再読み込み．
- 通知と，ネイティブメニュー・入力欄を含む録音パネルの非表示ウインドウでの描画．実デスクトップ上の操作確認とは区別します．
- 未完了フォルダー検出，保存先への書き込み失敗時のデータ保持，壊れたセグメントがある場合の一部回復と元データ保持．

合成テスト音声の保存先はテスト出力の`Test artifacts:`に表示されます．本物の会議音声は使いません．実施結果は`Tests/VALIDATION.md`に記載します．

## 手動テスト

各テストは短い試し録音を保存して，**相手と自分の両方が聞こえることを再生で確認**してください．メーターだけでは完成ファイルの確認になりません．

1. **Zoom＋AirPods入力・出力**：macOSとZoomの出力をAirPodsに設定します．アプリの入力にもAirPodsを選びます．Zoomで通話し，相手と交互・同時に発声して録音します．相手をイヤホンで聞き続けられること，出力先が変わらないこと，両音声・左右・入力形式・保存結果を確認します．TeamsとブラウザーのMeetでも同様に確認します．
2. **AirPods出力＋Mac内蔵マイク入力**：出力はそのままに，アプリの入力をMac内蔵マイクへ変更して新規録音します．両音声を確認し，前項との帯域・音質の違いを比較します．USBマイクでも選択を確認できます．
3. **ミュートの独立性**：Zoomだけをミュートした状態で話し，本アプリでは声が残ることを確認します．次に本アプリのマイク録音をオフにして話し，自分の声だけが保存から外れ，相手は残ることを確認します．オンへ戻した後も確認します．スピーカー経由の回り込みと区別するためAirPodsを使用します．
4. **AirPods切断・再接続**：録音中にAirPodsを切断します．切断通知，停止・保存結果，代替マイクへ勝手に移らないことを確認します．再接続後は通知と一覧を確認し，手動で新しい録音を開始します．出力のみAirPodsの場合も，形式変更時の停止表示を確認します．
5. **1時間程度の連続録音**：開始時と終了時に，同じ音を相手側とマイク側で同時に記録できるテスト音源などを使って同期差を比較します．人の会話の反応時間を音ずれと混同しないでください．アクティビティモニタで5分後・30分後・60分後のメモリー／CPUを記録し，メモリーが録音時間に比例して増えないことを確認します．分割境界ごとの無音，クリップ，保存時間，完成ファイルの長さも確認します．
6. **回復・エラー**：45秒以上録音後，テスト用途でアプリを強制終了し，再起動して未完了録音を回復します．確定済み30秒以上が戻り，末尾の損失があり得ることを確認します．許可拒否，選択マイク未接続，書き込み不可の保存先でも明示的なエラー表示を確認します．容量不足は実ディスクを埋めず，小容量のテスト用ボリュームで確認してください．

## 追加機能の手動テスト

1. **マイクのみ**：システムオーディオの許可に依存せず，Mac内蔵マイクを選んで30秒程度話し，停止・保存して声が左右から聞こえることを確認します．相手側入力待ちの警告が出ないことも確認します．
2. **会議通知**：Otologを起動して会議候補の通知をオンにします．Zoom／Teamsの通話やマイクテストを開始し，約3〜6秒後に通知が出ることを確認します．「今はしない」では録音されず，同じ通話中に通知が繰り返されないことを確認します．別の通話では「録音開始」を押し，検知対象と現在のマイク設定で録音されることを確認します．
3. **Meet通知**：対応ブラウザーでGoogle Meetへ参加し，マイクを使用します．アクセシビリティ未許可では一般的なブラウザー会議候補として通知されることを確認します．任意の会議名確認を有効にして許可し，タイトルが取得できる場合にGoogle Meetと表示されることを確認します．完全ミュート参加では見逃す場合があるため手動録音も確認します．
4. **ポップアップ**：「通知をプレビュー」で通知の位置，ボタン，30秒での非表示，フォーカスが会議から移らないことを確認します．プレビューは録音しません．
5. **会議名・JSTと名前変更**：会議名を取得できるタイトルの会議を検知し，通知後のパネルに会議名が入り，その名前で保存されることを確認します．会議名を取得できない場合はJSTの開始日時名になることを確認します．「停止時に保存名を確認」をオンにして名前を変更し，再生できることを確認します．キャンセルでも既定ファイルが残り，既存の別ファイルを指定しても上書きされないことを確認します．鉛筆ボタンからの変更も試します．

## Apple公式資料とSDK確認

- [Capturing system audio with Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)：Tap／Aggregate Deviceの作成と解放，システム音声許可，`NSAudioCaptureUsageDescription`．同サンプルとSDKの`AudioHardwareTapping.h`はProcess TapをmacOS 14.2以降としています．本アプリの最小OSは15です．
- [kAudioAggregateDeviceTapAutoStartKey](https://developer.apple.com/documentation/coreaudio/kaudioaggregatedevicetapautostartkey)：再生データ到着まで開始を待つオプションです．ローカルSDKの`AudioHardware.h`でも定義を確認しています．
- [AVCaptureSession.synchronizationClock](https://developer.apple.com/documentation/avfoundation/avcapturesession/synchronizationclock)：外部データとの時刻同期．SDKの説明に従い`CMSyncConvertTime`でホスト時計へ変換します．
- [kAudioProcessPropertyIsRunningInput](https://developer.apple.com/documentation/coreaudio/kaudioprocesspropertyisrunninginput)：Core Audioプロセスの入力利用を手掛かりにします．
- [AXIsProcessTrustedWithOptions](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)：対象アプリのウインドウタイトルを任意で確認する際の許可確認です．
- [AVAudioConverter](https://developer.apple.com/documentation/avfaudio/avaudioconverter)，[AVAudioFile](https://developer.apple.com/documentation/avfaudio/avaudiofile)：標準機能による形式変換と音声ファイルI/O．
- [AirPods高音質録音設定](https://developer.apple.com/documentation/avfoundation/avcapturesession/configuresapplicationaudiosessionforbluetoothhighqualityrecording)：iOS APIの説明だけでmacOS対応を推定せず，ローカルSDKのavailabilityも確認しています．

## 開発上の互換性

bundle IDは`local.tetsugo.MeetingRecorder`です．アプリ名をOtologへ変更する前の設定・権限との互換性のため維持しています．初回保存先は`~/Music/Otolog`ですが，保存先を設定済みの場合や旧版の`~/Music/MeetingRecorder`が存在する場合は元の場所を引き継ぎます．

Xcodeプロジェクトは`Scripts/generate-project.py`で再生成できます．通常のビルドにはPythonや再生成は不要です．このスクリプトはproject.pbxprojと共有スキームを上書きするため，Xcodeの設定を変更した場合は内容を確認してから使ってください．
